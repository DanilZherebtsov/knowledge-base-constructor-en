# knowledge-base-constructor-en

**The idea — an LLM wiki.** A project's sources are compiled once into a permanent, interlinked wiki; from then on the agent answers by reading it instead of re-deriving the same things from raw documents on every question.

A ready-made project for working with an AI agent: rules, the project memory (`wiki/`), a work plan, and the order of work with decisions, code, presentations, and roles — all already in place, nothing to attach. The same project works in **Claude Code**, **Codex** and **Qwen Code**.

- **How to download:** the **Code → Download ZIP** button on the [public mirror's](https://github.com/DanilZherebtsov/knowledge-base-constructor-en) page — it unpacks into a folder `knowledge-base-constructor-en-main`: that is the project, rename it and open it. Move the folder only as a whole: some files in it are hidden (`.claude/`, `.codex/`, `.qwen/`). Don't clone it (`git clone`): the archive leaves out the mirror's service files (`README.md`, `CHANGELOG.md`, `versions.json`, `migrations/`), while a clone pulls them in and links the folder to this repository.
- **`python3` is needed** (Mac, Linux) — the project's automatic checks run on it: reminders, protection of the documents you sent, the reply check. On Windows the project has not been tested: the check commands are written for Mac and Linux and most likely won't start there. The project's rules still apply — the agent works by them, just without the automatic checks.
- **The project's rules are in `AGENTS.md`.** Next to it lies a `CLAUDE.md` of one line `@AGENTS.md`: Claude Code reads the rules through it. Other programs don't use it; no need to delete it.
- **First setup — once, before the first conversation:**
  - **Claude Code** (terminal, VS Code, JetBrains, the Code tab) — nothing to set up.
  - **Claude Desktop** (a project, not the Code tab) — create a project and open its settings (**Project settings**): **Environment → Pre-approved folders → Add** — pick the project folder; **Memory → Project instructions** — paste the line "Before your first reply in every chat, read AGENTS.md from the project folder and follow it; if you can't open the file, say so. Write to files in this folder, not to the app's memory (MEMORY.md)." The project's automatic checks don't work in Claude Desktop — the rules hold as text.
  - **Codex** — when you first open the folder, Codex asks whether to trust it: choose "Trust and continue", not "Open restricted". Then type `/hooks`, approve this project's checks, and restart Codex. Without trust Codex reads only the first 32 KiB of the rules, and they are larger — the agent will tell you how to fix that. After some replies the reply check makes a short separate Codex run: when signed in with an API key, this costs money; with a subscription — it uses its limits; if you don't need it, tell the agent "turn the memory check off".
  - **Qwen Code** — open it in the project folder interactively (not `qwen -p`) and approve the project's checks when it asks, or type `/hooks`. The approval is dropped after updates that change the checks and after editing the project's `.env` file — then approve again. If you turned on folder trust in your Qwen Code settings, trust this folder too: otherwise it silently reads neither the rules nor the project's checks.
- **Open:** the folder in your program and just start a conversation: the agent asks what we'll be working on and records the answer in the project description.
- **You can work in several programs in turn.** All the project's knowledge is plain files (`wiki/`, `STATE.md`, the rules, documents) that any of the three reads. Before switching programs say "hand this off to a new chat": the conversation history and the program's built-in memory don't move. In the new program — its first setup, once.
- **Your own rules** — ask to have them written without program names, so any program can follow them; the agent writes one program's specifics into its file in `methodology/environment/`.
- **A project on version 2.x:** say "run maintenance" — the agent will offer the move to 3.0.0 and carry it out: your edits are kept, the move can be undone with one command; at the end the agent tells you what to do in the programs (the line in Claude Desktop, approving the checks in Codex and Qwen Code). The move needs a program with a terminal and network — Claude Code, Codex or Qwen Code; in Claude Desktop the agent will ask you to open the project there. **A project on version 1.x** — the same: first the move to 2.0.0, then, at the next maintenance in a new chat, to 3.0.0. The 1.x files (`base/`, `mechanics/`, `START-HERE.md`) — at the `v1-final` tag.
- **What next:** type `help` at any moment — the agent shows what it can do in this project; each program's specifics are in `methodology/environment/`. Once a week — "run maintenance": a check of the project memory and an offer to update if a new version is out.
- **Versions:** one for the whole project and all programs, [`versions.json`](versions.json); what changed — [`CHANGELOG.md`](CHANGELOG.md). The project carries its version number on line 3 of `AGENTS.md`; an update keeps your edits.
